# Заявки с сайта → Telegram

Небольшой сервис на FastAPI. Сайт отправляет форму на `POST /webhook/lead`, сервис проверяет данные, сохраняет заявку в базу и отправляет её в Telegram (в личку или в рабочую группу).

## Что умеет

- принимает JSON с полями `name`, `phone`, `email`, `message`, `source`
- проверяет данные: имя, телефон (приводится к `+7XXXXXXXXXX`), email; если что-то не так, возвращает `422` и понятное описание ошибки
- требует ключ в заголовке `X-API-Key` и не запускается со стандартным `change-me`
- отсеивает спам-ботов через honeypot: скрытое поле `website`, человек его не видит и не заполняет
- **заявки не теряются**: сначала запись в SQLite, потом отправка. Если Telegram недоступен, заявка помечается `notified=0` и досылается вместе со следующей
- `GET /leads.csv` отдаёт все заявки для Excel (тоже по ключу), `GET /health` нужен для мониторинга

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:get_app --factory --port 8000
```

| Переменная | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | куда слать: ваш ID или ID группы (у группы он с минусом) |
| `API_KEY` | любой длинный секрет, сайт передаёт его в `X-API-Key` |
| `ALLOWED_ORIGINS` | домены сайта для CORS через запятую |

Документация API генерируется автоматически и открывается на `http://localhost:8000/docs`.

## Пример

```bash
curl -X POST http://localhost:8000/webhook/lead \
  -H "X-API-Key: <ваш ключ>" -H "Content-Type: application/json" \
  -d '{"name": "Иван Петров", "phone": "8 912 345-67-89", "message": "Нужен бот"}'
```
```json
{"ok": true, "id": 1}
```

В Telegram придёт:

```
🔔 Заявка №1 (website)
👤 Иван Петров
📞 +79123456789
✉️ —
💬 Нужен бот
```

## Подключение к сайту

Лучше всего подключать через серверный вебхук: так умеют Tilda, WordPress-плагины форм и большинство конструкторов. Тогда ключ остаётся на сервере и никому не виден. Если отправлять форму прямо из браузера через `fetch`, ключ окажется в коде страницы. В таком случае `API_KEY` защищает только от случайных запросов, а основную работу делают `ALLOWED_ORIGINS` и honeypot.

## Тесты

```bash
pytest
```

Проверяются: сохранение и отправка, проверка ключа, ошибки валидации, honeypot, падение Telegram и досылка неотправленных заявок, CSV (включая защиту от формул в Excel). Вместо Telegram используется заглушка.
